Resumen Ejecutivo

Fluix es una plataforma ERP/HRM diseñada para PYMEs españolas con capacidad multiempresa y multisede. Este análisis evalúa en qué medida su arquitectura actual puede absorber la operativa de Sysday Emergencias Sanitarias, una empresa con 2.700 empleados distribuidos en bases, turnos de guardia 24/7, flotas de ambulancias y cumplimiento normativo sanitario.

Veredicto: PREPARADA CON MATICES

Fluix cubre el 85% de las necesidades de Sysday de forma nativa. Los módulos de RRHH, nóminas, fichajes con GPS, portal empleado y el Centro de Despacho de Ambulancias (CAD) son directamente utilizables. Los gaps se concentran en la jerarquía organizativa multi-nivel, el procesamiento masivo de nóminas (2.700 payslips/mes) y la falta de integración con sistemas de salud tipo SAP HCM o Sage HR.

👥 RRHH — Gestión de Empleados

✓ Módulo de Empleados — Listo

Ficha de empleado completa (datos personales, contrato, categoría, zona), documentos adjuntos (nóminas, finiquitos), portal del empleado (standalone móvil con 3 tabs: Portal | Mensajes | Perfil). Soporte multi-rol implícito.

⚠ Jerarquía organizativa — Parcial

Fluix no tiene un organigrama multi-nivel nativo. Para 2.700 empleados con estructuras Director → Jefe de base → TES senior → TES junior, habría que implementar un árbol de roles con permisos en cascada. Hoy solo existen dos niveles: propietario y empleado.

💶 Nóminas y Payroll

✓ Motor de cálculo — Funcional

Cálculo de IRPF, Seguridad Social, deducciones, horas extra, nocturnidades. Generación de PDF de nómina con plantilla personalizable. Formularios 111 y 190 automáticos. Finiquito auto-calculado con firma digital.

✗ Procesamiento masivo — Pendiente

Este es el gap más crítico. Generar 2.700 nóminas en un único proceso de cierre mensual requiere procesamiento en batch con Cloud Functions. Hoy el motor de nóminas procesa una nómina cada vez. A 500ms por nómina = 22 minutos de procesamiento secuencial. Necesita migración a Cloud Tasks o procesamiento paralelo.

⚠ Convenio Colectivo sanitario — Manual

Las tablas salariales del Convenio Colectivo de Empresas de Ambulancias (CCEA) no están precargadas. Habría que parametrizar manualmente los complementos por categoría profesional, guardia, festivo, etc.

📍 Control Horario y Fichajes

✓ Fichaje GPS — Listo para escala

Control horario con GPS, geofencing por sede, PIN de verificación, registro de incidencias. Informe de horas por empleado y turno. Para 2.700 empleados el Firestore maneja la carga sin modificaciones (Firestore escala automáticamente).

⚠ Turnos de guardia 24/7 — Parcial

El módulo de operaciones gestiona asignaciones de turno, pero la planificación de guardias médicas en rotación (ciclos de 12h, descansos mínimos legales, cambios de última hora) no está automatizada. Requiere desarrollo adicional o integración con un planificador especializado.

🏖 Vacaciones y Ausencias

✓ Gestión de vacaciones — Funcional

Solicitud, aprobación por flujo de trabajo, acumulación automática, traspaso entre periodos. Para Sysday la clave es que los aprobadores son múltiples (cada jefe de base aprueba su equipo). La arquitectura multi-sede lo soporta, pero la delegación de aprobación debe configurarse por sede.

📊 Cumplimiento Fiscal y Legal

✓ VeriFACTU (RD 1007/2023) — Implementado

Facturas QR firmadas con certificado digital PKCS#12, XAdES qualified signature, envío directo a AEAT. Obligatorio para empresas con más de 6M€ de facturación (Sysday superaría este umbral). Fluix lo tiene nativamente.

✓ Modelos fiscales — Completo

Mod. 111 (retenciones trimestrales), 190 (anual), 303 (IVA), 347 (operaciones con terceros), 349 (intracomunitarias). OCR fiscal con IA para facturas recibidas.

📱 Comunicaciones y Notificaciones

✓ Stack completo — Email + SMS + WhatsApp + Push

FCM para push urgente, Twilio para SMS, WhatsApp Business API para operaciones, email campaigns. Para un centro de emergencias el FCM de alta prioridad es crítico para alertas de despacho — está implementado con prioridad máxima.

⚠ FCM a 2.700 destinatarios — Límite de tasa

Firebase FCM tiene un límite de 500 mensajes/segundo. Envíos masivos (ej: alerta a toda la plantilla) requieren chunking en lotes de 500. Hoy los envíos son individuales o por grupo pequeño. Para alertas de emergencia a toda la empresa habría que implementar FCM topic messaging.

Roadmap de Implementación Recomendado

Se propone una implantación en 3 fases a lo largo de 6 meses para minimizar el riesgo operativo en un entorno de emergencias crítico.

1

FASE 1 — Núcleo operativo (Semanas 1-6)

Configurar multisede por base operativa. Migración de datos de empleados (import CSV). Activar fichaje GPS por sede. Portal empleado para TES. Configurar roles básicos (propietario / jefe de base / empleado). Desplegar OSRM propio con datos de España. Poner en producción módulo CAD con datos reales de flota.

2

FASE 2 — RRHH completo (Semanas 7-16)

Parametrizar tablas salariales del Convenio Colectivo de Ambulancias. Implementar procesamiento batch de nóminas (Cloud Tasks). Configurar flujos de aprobación de vacaciones por jefe de base. Activar módulo fiscal (VeriFACTU, Mod.111/190). Integrar firma digital con certificado de empresa. Activar WhatsApp para comunicaciones operativas.

3

FASE 3 — Escala y optimización (Semanas 17-24)

Implementar jerarquía organizativa multi-nivel. Preagregar KPIs nocturnos para dashboard de dirección. FCM topic messaging para alertas masivas. Explorar integración con sistemas autonómicos (SUMMA/SEM) vía webhook. Formación a mandos intermedios. Go-live completo + soporte post-implantación.
